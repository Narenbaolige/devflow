## 5. 架构层面真实情况

### Agent 工作方式：Prompt 工程 vs Tool Calling

```
蓝图描述：                        实际实现：
Agent 使用 read_file 读源码  →  Agent 从 Prompt 中推断代码结构
Agent 使用 grep 搜索代码     →  不调用任何工具
Agent 使用 glob 匹配文件     →  直接生成输出 JSON
Agent 通过 sandbox 跑测试    →  graph.py 节点代为执行
```

**影响**：Developer Agent 无法读取目标仓库的真实源文件，patch 基于推断生成（这也是 D5 中需要三层 patch 兜底的根本原因）。

**评价**：这不是错误——在无 tool-calling 的情况下，Agent 仍能通过 Prompt 工程生成合理的输出（D5 验证通过 + 20/20 评测）。但蓝图中"Agent 像人类工程师一样浏览代码仓库"的设想并未实现。这是两周冲刺中合理的架构简化。

### 沙箱安全模型

```
蓝图要求：                        实际实现：
Docker 容器                      LocalSandbox (subprocess)
--network none                  shell=True（系统网络访问）
--read-only 根文件系统            完全读写
--cpus 1 --memory 512m          无资源限制
超时 300s                        超时 300s ✅
```

`docker.py` 代码完整（148 行），但从未在真实流程中启用。默认 `SANDBOX_MODE=local`。

### Checkpointer 持久化

```
蓝图：SQLite 零配置持久化，kill -9 后重启恢复
实际：MemorySaver（默认），PostgreSQL（可选），无 SQLite
```

| Backend | 跨重启持久化 | Kill -9 安全 | 默认 |
|---------|:----------:|:----------:|:----:|
| MemorySaver | ❌ | ❌ | ✅ |
| PostgreSQL | ✅ | ✅ | ❌ 需配置 |
| SQLite | ❌ 未实现 | — | — |
