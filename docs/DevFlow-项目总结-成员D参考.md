# DevFlow 项目总结

> 给成员 D 的参考文档——项目是什么、要交付什么、怎么运作的

---

## 一、项目是什么

**DevFlow** = 一个自动化的 AI 软件工程助手。

> 你给它一个 GitHub 仓库地址 + 一句需求描述，它自动帮你改代码、跑测试、做审查，最后告诉你改好了没有。

类比：一个 AI 版的 mini 软件团队，24 小时值班。

---

## 二、最终交付物

| 类别 | 具体内容 |
|------|------|
| **后端服务** | FastAPI，6 个 API 端点，跑在 `localhost:8000` |
| **工作流引擎** | LangGraph 状态图，11 个节点 + 5 条条件路由 |
| **4 个 AI Agent** | Requirement（需求分析）、Planner（方案设计）、Developer（写代码）、Reviewer（审查+安全检测） |
| **沙箱环境** | 自动 clone 仓库 → 安装依赖 → 运行 pytest，返回测试结果 |
| **Web 前端（你做的）** | 3 个页面：创建任务 / 任务详情 / 评测对比 |
| **评测数据** | 20 条测试任务 + 消融实验（单 Agent vs 多 Agent） |
| **实验报告** | 对比数据 + 图表 + 案例分析 |
| **一键启动** | `start.bat` 双击开前后端 |

## 三、核心运作流程

```
用户在 Web 页面提交：{ 需求: "修 Bug", 仓库: "github.com/xxx/repo" }
                              │
                              ▼
                    ┌─────────────────┐
                    │  📋 Requirement  │  读需求 → 输出验收条件
                    │     Agent        │  例: "要给 factorial 加参数校验"
                    └────────┬────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │  📝 Planner      │  看代码仓库结构 → 设计修改方案
                    │     Agent        │  例: "改 math_utils.py 的 factorial 函数"
                    └────────┬────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │  💻 Developer    │  生成代码 Patch（unified diff 格式）
                    │     Agent        │  告诉你要删哪行、加哪行
                    └────────┬────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │  🐳 沙箱执行     │  clone 仓库 → git apply → pip install → pytest
                    │                 │  输出: 10 passed / 2 failed / 0 error
                    └────────┬────────┘
                             │
                    ┌────────┴────────┐
                    │  测试通过了？     │
                    └────────┬────────┘
                   ✅ 通过    │    ❌ 失败
                             │         │
                             │    ┌────┴────┐
                             │    │ 返工循环  │ ← Developer 根据反馈重新改
                             │    │ (最多3次) │
                             │    └────┬────┘
                             │         │
                             ▼         ▼
                    ┌─────────────────┐
                    │  🔍 Reviewer     │  代码审查 + 安全检查
                    │     Agent        │  检查 SQL 注入、硬编码密钥、路径遍历
                    └────────┬────────┘
                             │
                             ▼
                    ┌─────────────────┐
                    │    ✅ 完成       │  或 ❌ 三次迭代后放弃
                    └─────────────────┘
```

## 四、两种运行模式

| | Mock 模式 | 真实模式 |
|------|:--:|:--:|
| Agent 调用 | 假数据，秒回 | 真实 DeepSeek LLM，3-7 秒/个 |
| 沙箱执行 | 假数据，永远通过 | 真实 clone + pytest |
| 成本 | 免费 | ~$0.001/任务（不到 1 分钱） |
| 适用场景 | 调试、演示、前端开发 | 真正修 Bug |
| 切换方式 | `.env` 里 `DEVFLOW_USE_MOCK=true` | `.env` 里 `DEVFLOW_USE_MOCK=false` |

## 六、你在答辩时可以演示什么

1. **双击 `start.bat`** → 两个窗口自动启动
2. **打开 `http://localhost:5173`** → 创建任务页
3. **填需求 + 仓库 URL → 点创建** → 自动跳转详情页
4. **实时看到**：左侧 Agent 进度逐个亮起 + 右侧 Diff 代码变化 + 测试结果面板
5. **点"评测对比"** → 看柱状图 + 雷达图 + 对比数据
6. **回到首页** → 底部"最近任务"找回历史任务
